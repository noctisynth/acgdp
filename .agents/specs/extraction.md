本文定义现阶段可交付的输入、格式识别、递归、密码、输出、安全和验证行为。`--jobs 2` 启用跨层流水线，其中 7z 外层到非 solid RAR 内层可在内层归档尚未写完时启动；其它布局仍以完整条目为界。

## 1. 用户流程与 CLI

- 输入为单个本地文件；不带参数运行时显示完整帮助并正常退出。仅解压时要求 `<INPUT>`。
- 根据文件内容识别格式，后缀可以是 `.zip`、`.7z`、`.rar`、`.jpg`、`.png` 或其它名称。
- `-p` 提供各层共用密码；`--ask-password` 使用 `inquire` 在同一行显示带前缀的中文提示、读取一次密码并用星号掩码，回车后只显示固定数量的星号。输入中的星号在启用颜色时着色；`--color never` 和 `NO_COLOR` 下保持无色。输入时掩码数量会反映密码长度；未加密时可省略密码。
- 默认输出到输入文件旁的「输入文件名.extracted」目录；`-o` 可指定输出目录。
- 默认删除解出的中间压缩包，只保留原始输入和最终内容；`--keep-intermediates` 保留中间包。
- `--max-depth` 默认 32 层，`--max-gib` 默认所有层累计写出 20 GiB，可由用户调整。
- `--jobs` 接受 1 或 2，默认 2；设为 1 时使用串行递归，设为 2 时对每个嵌套层建立有界队列和下一层工作线程，使连续多层的解压可以重叠。并行阶段数受 `--max-depth` 限制；同层条目仍按顺序处理。
- 帮助、进度和错误在终端中着色；`--color auto|always|never` 控制颜色，默认 `auto`。解压期间显示精简的层级、格式和归档名称。交互终端为 ZIP、7z 各层显示按该层声明解压大小计算的字节进度条；RAR 尤其是增长中的 RAR 无可靠总量时只显示已写出字节与活动指示，不显示虚假的百分比。并行层各有独立进度，进度条不是全任务百分比；重定向输出只写逐层记录和完成摘要。普通进度不显示内部临时目录或 Windows 扩展路径前缀；成功时显示输出目录、累计写出量和耗时。

## 2. 识别与格式后端

| 格式 | 识别与提取 | 边界 |
| --- | --- | --- |
| ZIP | `zip` 验证归档结构；`ZipArchive` 支持前置非 ZIP 数据 | Rust crate；加密 ZIP 使用同一密码 |
| 7z | 扫描 7z 签名并记录偏移；`sevenz-rust2` 使用偏移读取器解压 | Rust 实现；支持图片前缀与加密归档 |
| RAR | 扫描 RAR4/RAR5 签名；`unrar-ng` 提取 | Rust API 包装 UnRAR C/C++；许可独立 |

7z 分卷输入从 `.001` 开始；同目录中按数字递增的后续分卷作为一个逻辑文件读取，原始分卷不改动，也不预先拼接大文件。缺少必要分卷时给出错误，不交付部分结果。文件起点为标准 ZIP、7z 或 RAR 签名时可直接识别；带图片前缀的文件仍扫描内部签名。

识别不依赖扩展名。图片与压缩包拼接时，前置图片数据仍可保留；每个解出的普通文件都重新接受内容探测。ZIP 从文件起点开始且结构验证成功时可直接判定，无须再次全文件扫描；7z 和 RAR5 签名候选须校验格式头的 CRC，RAR4 候选须通过后端打开验证，避免普通游戏文件里的偶然字节被误判。其它候选仍可能扫描整个文件，因此大文件性能优化需要单独验证，不得直接删去图片附加包识别能力。

## 3. 递归与交付

1. 初始输入解到最终输出目录同一父目录下的临时目录。
2. 遍历该层解出的普通文件；发现内层压缩包时，在其所在目录建立另一临时目录并解压，使用相同密码和全局写出预算。
3. 先处理内层临时目录中的嵌套包，再把该层最终内容合并到原压缩包所在目录。目录可合并；同名文件或文件与目录冲突时报错，不覆盖。
4. 达到深度上限后仍发现压缩包则失败。所有层成功后，才将最外层临时目录重命名为最终输出目录。

流水线模式在每层普通文件完整写出后，将其送往下一层工作线程；该线程处理内层归档时同样向更深一层派发，直至深度上限。对任意一层 7z 写出的非 solid RAR，可在文件尚在写入时识别并提取已完整的 RAR 条目；到达临时文件末尾时等待更多字节、重开并跳过已成功处理的条目。外层完成后仍需读到真实归档结束，才能合并结果。solid RAR、ZIP 与内层 7z 仍待文件完成后处理。每层的工作队列有界、结果在独立临时目录处理；各阶段成功后按原条目顺序合并。写出预算在线程间原子共享；任何阶段失败都不得交付部分输出。

原始输入始终保持不变。已存在的输出目录不能覆盖；任意层失败时不得交付部分输出目录。`--keep-intermediates` 只影响中间压缩包是否保留，不改变递归深度和内容检查。

## 4. 不可信归档约束

- 拒绝绝对路径、父目录跳转、空路径和符号链接；不能让归档条目写出当前临时目录。
- ZIP 与 7z 按实际写出字节扣减累计预算；RAR 在提取前检查声明大小，并在提取后用实际文件大小扣减预算。
- 对所有层复用一个预算。上限是累计写出量，不等于最终目录大小；多层 10 GiB 归档可能需要显式调高 `--max-gib`。
- 密码不写入日志。`-p` 可能出现在进程参数中，交互使用优先 `--ask-password`。

## 5. 验收与现有限制

`cargo build` 和 `python tests/smoke.py` 覆盖多层 ZIP、伪装后缀、有效 PNG 后附加 ZIP/7z/RAR、RAR3/RAR5、混合格式、加密 ZIP/7z、颜色模式、失败清理、深度限制和符号链接拒绝。部分 7z/加密 ZIP 样例需要测试机安装 7-Zip 来生成夹具；运行 `acgdp` 不依赖 7-Zip。

分卷 RAR 与不常见条目尚需样本验证。真实 GB 级分卷 7z→图片前缀、加密文件头的 RAR5→游戏文件已验证，记录见 [样本验证](../spikes/0002-real-split-archive.md)。字节级重叠目前只覆盖 7z→非 solid RAR；ZIP、内层 7z、solid RAR 和无全文件扫描仍需独立实现。提交任何流水线性能改动前，须对改动前后同一夹具交错运行基准，覆盖至少三层嵌套链、多条目布局和现有真实样本；记录输出一致性与时间分布，发现回归须修复或明确回退。

Windows 中文密码提示的代码页兼容验证与交错基准见[交互提示验证](../spikes/0004-password-prompt.md)。
