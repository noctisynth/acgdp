# acgdp RFC 工作流

RFC 记录尚未确认、可能改变模块责任、格式兼容性、安全或资源边界的提案。已经生效的契约维护在 `../specs/`，实施差异维护在 `../todos/`；RFC 不代替任一者。当前没有待决 RFC。

## 状态

- `Draft`：探索问题、候选方案、取舍和验收方式；不构成实现依据。当前待决：[RFC 0001：尚在写入的内层归档解压](0001-byte-streaming.md)。
- `Accepted`：关键边界经用户确认，随后同步设计索引、Active Spec 和实施清单。
- `Rejected`：未采用，保留理由供后续参考。
- `Superseded`：被后续 RFC 替代，链接替代文件。

## 编号与推进

文件使用四位递增编号和简短主题，例如 `0001-streaming-extraction.md`。提案应描述现状、目标、非目标、格式差异、性能证据、安全与兼容影响、候选方案和待决问题。接受后按 `../DESIGN.md` 的依赖边界更新 Spec，再实施和验证。
