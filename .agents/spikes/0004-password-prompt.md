# Windows 密码提示代码页验证

> 日期：2026-09-29；Windows，Rust 1.98.1

原先 `rpassword::prompt_password` 将中文提示的 UTF-8 字节直接写入 Windows 的 `CONOUT$`；用户终端按本地代码页解释时会显示乱码。改为 `inquire` 0.9.4 的 `Password` 提示，使用 `crossterm` 后端，并关闭默认的二次确认。提示颜色遵循 `--color` 和 `NO_COLOR`；输入保持隐藏，完成后只显示固定数量的星号。

在 Windows 控制台执行 `chcp 936` 后，分别以 `--color never` 和 `--color always` 对本地 RAR 夹具运行 `--ask-password`：两种模式下中文“压缩包密码”均正常显示，输入不回显，输入一次后解压成功。无参数帮助、构建、冒烟测试和严格 Clippy 检查也通过。

提交前对改动前后的发布版二进制运行 `python tests/compare_pipeline.py <旧版> <新版> --rounds 8`，各场景每版 16 次交错：单链 0.102/0.102 秒（新版/旧版比 0.997），多个内层包 0.414/0.408 秒（比 0.985），四层链 0.334/0.316 秒（比 0.946）。这些夹具不走交互输入，检验的是新增依赖对启动和常规解压的影响；没有观察到性能回归，不能据此推断交互界面的响应时间。

## 后续界面修正

用户实测发现 `inquire` 的隐藏密码模式将光标移到下一行。源码中该模式在绘制提示后立即输出换行，这是隐藏输入时的预期布局。改用 Rust 标准输出写出同一行中文提示，再由 `rpassword::read_password` 隐藏读取；不输出占位星号或密码长度。进度改由 `indicatif` 显示交互活动指示，普通日志只保留层级、格式和文件名。

以 `chcp 936` 的交互终端运行，中文提示正常，光标停在提示末尾；输入不回显，回车后解压成功。`cargo build`、`cargo fmt --check`、`python tests/smoke.py` 和严格 Clippy 检查通过。提交前对旧版与新版发布二进制运行两轮交错基准，每轮每场景每版 16 次：第一轮单链 0.108/0.103 秒、多内层包 0.401/0.419 秒、四层链 0.347/0.330 秒（旧/新）；第二轮依次为 0.100/0.098、0.383/0.388、0.311/0.321 秒。多内层包与四层链的微小方向变化不稳定，未发现一致的性能回归；该基准只覆盖非交互解压。

## 恢复 Inquire 的同行掩码样式

用户更偏好 `inquire` 的前缀和完成态样式。将密码提示重新交给 `inquire`，明确设置 `PasswordDisplayMode::Masked`；这样输入光标随星号保持在提示行，完成后仍使用固定八个星号的默认格式。与 `Hidden` 不同，输入过程的星号数量会反映密码长度。

在 `chcp 936` 交互终端分别以 `--color always` 与 `--color never` 验证中文提示、同行星号与完成态；两次均成功解压。`cargo build`、`cargo fmt --check`、`python tests/smoke.py` 和严格 Clippy 检查通过。提交前对旧版与新版发布二进制运行交错基准，每场景每版 16 次：单链 0.105/0.102 秒、多内层包 0.393/0.390 秒、四层链 0.314/0.313 秒（旧/新），输出一致，未观察到回归。
